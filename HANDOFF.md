# Handoff

_Written 2 Nov 2026. Supersedes the earlier handoff, which described the Day 7
document-writing pass — that work is finished and committed._

## Objective

Deploy Proofly: the API as a container on Render, the web app on Vercel, against
Neon Postgres. `docs/runbook-deployment.md` is the authority; this is only where
it got to.

## Current status

**Phases 0–3 of the runbook are done. Phase 1's code is written and verified
against a real container, not just reasoned about.** What is left is Phase 4
(Render) and Phase 5 (Vercel), both dashboard work that needs the account
holder, plus the Phase 6 smoke test.

Three things in the deployment config could never have worked, each confirmed
against the platform's own documentation and then fixed:

| Was | Why it fails | Now |
| --- | --- | --- |
| `preDeployCommand` on a `free` Render plan | pre-deploy is paid-only, so the schema is never applied | migrations run from the container's `CMD`, idempotent |
| `disk:` on a `free` Render plan | free instances cannot attach one | removed; ephemeral receipts recorded in `CHANGELOG.md` against BR-10 |
| `crons` in `vercel.json` | Vercel cron sends GET, no custom headers, functions only — the endpoint is POST behind `x-cron-secret` | `.github/workflows/reminders.yml` |

Two further traps were caught on the way: Render and Vercel would both have
deployed `main` (which holds only a generated README) instead of `master`, and
`DATABASE_SSL=false` — the line `.env.example` ships — evaluated to `true`,
because `Boolean('false')` is `true`.

## Verified, by running it

- Image builds (`docker build -f apps/api/Dockerfile .`), and against an **empty**
  database applied **7/7 migrations** from the start command.
- `/api/v1/health` → `{"status":"ok","database":"up"}`.
- `/api/docs` → **404** under `NODE_ENV=production`, which is correct.
- Reminders endpoint → **401** no secret, **404** on GET (the Vercel defect,
  reproduced), **200** `{"users":0,"reminders":0}` on correct POST.
- The workflow's exact `curl` → 200 with the right secret, 401 with a wrong one.
- `apps/web` builds standalone from a clean checkout — `npm ci` and
  `vue-tsc && vite build` both exit 0 — which is how Vercel builds it.
- Suites: **44** API unit, **174** API e2e, **216** web unit. All green.

## Remaining — needs your accounts

1. **Render** → New → Blueprint → this repo. Only five values need typing, the
   rest is in `render.yaml`: `DATABASE_URL` (Neon, **pooled**), `WEB_ORIGIN`,
   `APP_URL`, `SMTP_PASS`, `MAIL_FROM`. `JWT_SECRET` and `CRON_SECRET` are
   generated by Render — never copy the development ones.
2. **Vercel** → import the repo, root `apps/web`, and set **Production Branch =
   `master`** (Settings → Git). It defaults to `main`, which is empty.
3. **Correct `vercel.json`'s rewrite** if Render assigned a hostname other than
   `purchase-tracker-api.onrender.com`. Every API call 404s until it matches.
4. **Come back and set `WEB_ORIGIN` and `APP_URL`** on Render to the real Vercel
   domain. Chicken-and-egg: the domain does not exist until step 2. The browser
   cannot use the API until this is done — `WEB_ORIGIN` is the CORS allow-list,
   `APP_URL` is what reset links are built from.
5. **GitHub repository secrets** `API_BASE_URL` and `CRON_SECRET` (Settings →
   Secrets and variables → Actions), then Actions → *Daily reminders* → Run
   workflow, once, to prove the digest before 08:00.
6. **Phase 6 smoke test** against the live pair.
7. **Confirm CI's first run passed** — the mirror now has `master`, so it has
   fired, but nobody has read the result. There is no `gh` CLI on this machine.

## Known, accepted

- **Receipts do not survive a restart in production.** Free instance, no disk.
  Recorded in `CHANGELOG.md`; the fixes are `plan: starter` plus the `disk:`
  block that `render.yaml` still documents, or a second `Storage` implementation
  (the interface is three methods wide for exactly this reason).
- A failed migration now takes the service down rather than cancelling the
  release — the price of `CMD` over a paid pre-deploy step. Both files say how
  to move it back.
- The reminders workflow is paused after 60 days with no commits to the repo.
- **Never run `npm run seed` against production** — it creates an account whose
  password is published in this repository.
